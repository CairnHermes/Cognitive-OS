Let's design architecture:

Name: "Aegis-Cortex" or "Cognitron"? Maybe "Tesseract"? Need concrete.

Core principle: a persistent "World State Ledger" (WSL) + "Cognitive Kernel" (CK) + "Policy Engine" + "Safety Gateway". The kernel is a large transformer/SSM hybrid with explicit latent state vector and memory attention. It operates on "cognitive operations" (COs): observe, hypothesize, plan, act, verify, commit. Each operation emits typed JSON records to ledger. The model's outputs are not final; they are proposals validated by verifier and executed via tools.

Memory architecture:
- Working memory: KV cache of current context + latent state (RNN/SSM state) maintained across session. Size: e.g. 128k tokens, 16k latent slots.
- Episodic memory: append-only event log in object store (S3) + Cassandra/Postgres; events: observations, actions, outcomes, rewards, user utterances. Indexed by time, entity, task, embedding.
- Semantic memory: vector DB (Qdrant/Milvus) + knowledge graph (RDF/property graph) for entities, relations, facts with confidence and provenance. Updated by consolidation process.
- Procedural memory: library of skills/mcps: code snippets, tool sequences, policies; stored as versioned packages. Learned via skill induction.
- Parameter memory: model weights + adapters; long-term learning via offline RL and fine-tuning.
- Retrieval: hybrid retrieval: BM25 + dense + graph traversal + recency/importance scoring. Use "memory router" small model to choose.
- Consolidation: nightly job extracts salient facts, prunes duplicates, updates graph, distills episodes into summaries/skills.

Reasoning/planning loop:
- Input: goal, context, constraints.
- Loop: (1) clarify goal and constraints; (2) retrieve relevant memory/world state; (3) generate candidate subgoals/plan using hierarchical planner (LLM + search); (4) simulate/evaluate with world model and verifier; (5) select executable next action; (6) execute via tool; (7) observe outcome; (8) update belief and plan; (9) terminate or escalate.
- Use MCTS over "plan nodes" where node = (state, belief, action). Policy = LLM proposes actions. Value = learned reward model + world model rollout. Verifier = separate model checks logical validity, safety, resource constraints. Replanning triggers: tool failure, new evidence, goal change, low confidence.
- Planning horizon: short-term 5-20 actions, long-term task decomposition with milestones. Use beam width 4-8, depth 6.
- Belief state: set of hypotheses with probabilities; world model predicts observations.

Learning/self-improvement:
- Online: experience replay from ledger; reward signals: task completion, user feedback, verifier scores, cost, safety incidents. Use RL (PPO/GRPO) on policy with constrained objective. But weights not updated in production maybe via shadow model; update adapters.
- Self-generated curriculum: propose tasks from knowledge graph gaps and failed traces; solve with smaller model; verify; add to training set.
- Skill distillation: successful tool sequences compiled into reusable "skills" (Python/MCP servers) and fine-tuned.
- Meta-learning: train on task families; learn to plan, verify, retrieve.
